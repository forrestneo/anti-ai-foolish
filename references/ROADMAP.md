# anti-ai-foolish 路线图（2026-09-16 定稿，原名去AI-Harness）

## 总目标
把"被微信判AI打回"变成一个可机械执行、可持续验证、可回归测试的工程问题。

## 三阶段

### 阶段一：规则层（✅ 已完成 2026-09-16）
- 1108条规则、13分库、720词条从23个skill机器收割
- 1080条在52片段朱雀标签语料上A/B验证，五态回写（confirmed 8 / reversed 10 / directional 13 / no_signal 68 / insufficient 981）
- 产出：scanner引擎 + Z分（r=0.813）+ preflight管线；端到端与朱雀实测对齐（0.91/0.93稿拦下、手术后稿放行）
- 里程碑 M1 ✅：harness能正确分拣"已知答案"的三篇考卷

### 阶段二：究极skill（← 本轮）
把本工程的机械力 + qu-ai-fingerprint 2.2的方法论 + 人工判据，封装成一个**自包含、经过验证**的skill，装进 ZCode 技能目录（~/.zcode/skills/anti-ai-foolish/），任何会话可直接调用。
- 自包含：规则库+引擎+管线随skill分发，不依赖外部路径
- 经过验证：①三篇考卷回归测试（拦截0.91/0.93、放行V7）②52片段分类力（Z分：AI侧26/30、human侧11/12）③全部阈值标注证据出处
- 内容分层：SKILL.md=工作流；references/=方法论细则（七刀/人工判据/豁免/发布纪律/证据链）
- 里程碑 M2：skill在三篇考卷上判定与朱雀实测100%一致，52片段分类力≥既有引擎

### 阶段三：skill评测（← 本轮）
对究极skill做一次系统评测，出评测报告：
1. **分类力**：52片段上skill机械判定 vs 朱雀真标签（准确率/召回/误报；并如实区分"Z分分类器"与"发布质量门"两种角色）
2. **修复力**：文章一、文章二经skill全流程手术 → harness复检前后对比（朱雀实测留用户）
3. **横评**：同一考卷上 vs 市售skill（remove-ai-flavor 19-24分分不出人机 / ai-flavor-remover 章节依赖崩溃 / 词表类skill无确认规则……本项目已有评测数据）
4. **边界**：机械上限0.8的方差去向（人工判据）、"只能抓AI不能证人工"
- 里程碑 M3：评测报告落档，skill版本冻结为 3.0.0-validated
